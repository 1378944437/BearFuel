## 1. 文档目的

本文将代码审查发现整理为可执行的整改计划，明确：

1. 当前已经完成的修改；
2. 尚待修复的问题及优先级；

4. 每项修复的实现方案、测试要求和验收标准；

本文不把“能运行”当作“数据可靠”。所有涉及金额、里程、油耗和统计的改动，都必须同时满足代码实现、边界测试和用户可解释性三个条件。

## 2. 总体结论

当前没有发现会无条件破坏全库的 P0 问题，但存在多项 P1 统计口径错误。这些问题在跨月、跨年、跨万公里阶段、未加满、漏记、里程回拨、换表、补录和多车辆导入时会产生不可对账的数据。

在核心整改已完成后，仍需将以下内容视为受限能力：

- XLS 通用 BIFF8 高级结构（`CONTINUE`、`FORMULA`、多工作表、DIFAT/MiniFAT 等）尚未完整支持；
- 导入写入、重算和派生回写尚未组成同一数据库事务，完整失败回滚仍需后续实现；
- 记录级派生值仍为兼容展示字段，汇总已使用完整周期原始值，但数据库精度与历史字段迁移仍需继续收口；
- 统计和导入的可靠性依赖输入记录日期、里程和金额事实正确；回拨、换表、未闭合周期仍会被标记为受限而不是被猜测修正。

以下数据在这些受限场景下不能作为严格审计结果使用：

- 月度、季度、年度周期报表的里程、平均油耗和每公里成本；
- 自定义范围、今年、近半年范围的累计里程和平均油耗；
- 每万公里阶段的里程、耗油量和平均油耗；
- 跨月、跨阶段未加满记录的油量归属；
- 里程回拨或换表后的累计里程；
- 补录、异常里程或换表场景下的“当前表显”；
- 外部备份中金额关系未校验的成本类数据；
- 导入后与小熊油耗原始油耗值的逐笔对照结果。

## 4. 整改原则

### 4.1 区分原始事实、派生值和展示值

- 原始事实：用户导入或录入的日期、表显里程、加油量、机显单价、机显金额、实付金额、油号、加满、漏记、亮灯、站点、备注；
- 派生值：本地算法计算的区间距离、百公里油耗、每公里成本；

原始事实不得被派生值覆盖。派生值可以重新计算，展示值不得反向写回原始字段。

### 4.2 统一统计基本单位

所有统计必须明确使用以下三种口径之一：

1. **交易口径**：按加油发生日期归属，统计加油量和实付金额；
2. **完整周期口径**：只统计从一次加满到下一次加满闭合的油耗、距离和成本；
3. **行驶区间口径**：按相邻有效表显里程差统计行驶距离。

同一张卡片不得把三种口径混在一起后使用“累计”“总计”等含义不清的标题。

### 4.3 不确定数据不得静默变成确定数据

- 无法解析的日期不得替换成当前时间；
- 未知的“是/否”不得默认成 false；
- 缺失金额或单价的推算必须带来源标记；
- 里程回拨、换表和跨车辆数据必须进入异常状态或被明确隔断；
- 统计无法闭合时显示“数据不足/未闭合”，不能显示看似精确的 0。

### P1-01 周期报表跨周期边界丢失里程 ✅ 已完成

- 状态：已实现。`getPeriodStats` 已改为在全量记录上用 `FuelCycleBuilder.build()` 一次性建立完整周期，按"结束加满记录所在周期"归属；交易口径（加油量、油费）与完整周期口径（里程、平均油耗、每公里成本）已分离；跨边界周期以 `boundaryCycleCount` 计数呈现，不再混入平均值。

- 位置：`lib/domain/statistics_service.dart:getPeriodStats`
- 触发：月度、季度、年度或按天分组时，完整周期跨越分组边界；
- 现象：每组第一条记录没有组外前序记录，里程差被丢弃，但该记录的完整周期油耗仍可能进入平均值；
- 影响：里程、油耗、每公里成本互相无法对账。

**修复方案**

1. 先在全量、按时间排序的记录上建立完整油耗周期；
2. 为每个周期保存起始时间、结束时间、起止里程、周期油量、周期费用和完整距离；
3. 统计分组时按“周期与统计范围的关系”分配，而不是对已切片记录重新调用 `sumConsecutiveMileage`；
4. 对完整周期跨越月份的情况提供明确策略：
   - 默认将周期归属到结束加满记录所在月份；或
   - 按里程/时间切分周期，但必须同步切分油量与费用；
5. 交易口径的油量、油费单独统计，不与完整周期油耗卡片混合。

**测试要求**

- 1/31 10000 km 加满，2/10 10500 km 加满；
- 跨季度和跨年度同样验证；
- 验证所有周期里程总和与完整周期明细一致；
- 验证“平均油耗”和“每公里成本”的分母、分子来源一致。

**验收标准**

- 不再出现“周期里程为 0、平均油耗非 0”；
- 周期报表每一条数据都能追溯到完整周期明细；
- 跨边界的归属策略在界面上可解释。

### P1-02 统计范围截断完整油耗周期 ✅ 已完成

- 状态：已实现。新增 `StatisticsService.getRangeCycleStats`（周期建立在全量记录上，只有完整包含在范围内的可信周期参与平均油耗/里程/每公里成本，边界相交周期仅计数）。统计页四大指标改为双口径：交易口径（加油量、实付金额）与完整周期口径（里程、平均油耗、每公里成本）分开呈现，自定义范围使用排他上界（次日 00:00）；存在边界周期时界面提示"另有 N 个完整周期跨越范围边界"。测试：`test/range_cycle_stats_test.dart`。

- 位置：`lib/presentation/screens/charts/statistics_screen.dart` 的范围过滤逻辑；
- 触发：今年、近半年、自定义范围从完整加油周期中间开始；

**修复方案**

默认建议：

- 只有完整包含在范围内的周期才进入范围平均油耗；
- 与边界相交但不完整的周期显示为“边界未闭合”，不参与平均油耗；
- 范围卡片分别标注“交易统计”和“完整周期统计”。

### P1-09 备份恢复没有金额一致性校验 ✅ 已完成

- 状态：已实现。恢复流程已引入 `BackupAmountIssueKind`（量价关系不符、优惠金额为负）与 `BackupConsistencyReport`，检查结果通过 `BackupRestoreResult.consistency` 回传界面展示。注："实付金额 ≈ 机显金额 - discountAmount" 的第三条关系校验尚未单列，随 P2 后续补强。

- 位置：`lib/data/database/database_helper.dart` 的备份恢复校验；
- 现象：只检查金额、油量、单价为正，没有校验量价和优惠关系；
- 影响：成本、费用结构和每公里金额被矛盾数据污染。

**修复方案**

恢复时执行软校验：

```text
机显金额 ≈ fuelAmount × unitPrice
实付金额 ≈ 机显金额 - discountAmount
```

考虑两位小数和优惠/手续费后使用明确容差。校验失败时：

- 默认拒绝恢复并列出具体记录；
- 提供“仅导入原始记录、标记为待核对”的安全选项；
- 禁止静默修正金额。

## 10. 本轮审查的最终判断

当前核心计算器在“连续加满、未加满后加满、漏记作为断点”三个基本场景下是自洽的；问题主要集中在统计边界、数据归属、异常里程、外部数据校验和派生值持久化，而不是基础公式本身。

在完成阶段一和阶段二之前，不建议把当前周期报表、阶段报表和自定义范围统计作为精确财务或里程审计依据。优先建立“完整周期模型”和“原始/派生分离”后，再继续优化展示与缓存，能够避免同一问题在多个统计页面重复修补。
